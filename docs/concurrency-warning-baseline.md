# Concurrency warning gate

CI compiles the complete app, CLI and test graph with `swift build --build-tests -Xswiftc -warn-concurrency`, then runs `python3 scripts/ci/check_concurrency_warnings.py --log ci-logs/swift-test-build.log`. A build failure remains a failure independently of this gate. The existing Swift 6 language-mode check remains a separate check and still omits the WhisperKit and Markdown dependencies.

Production concurrency diagnostics have zero allowance. `scripts/ci/concurrency-warning-baseline.json` records remaining test fixture migration debt from the linked CI run, after subtracting the categories addressed in this change. These allowances are provisional until the next complete Xcode CI build verifies the fixture changes; they are not proof that remaining fixtures are race-free. The current migration fixes actor-isolated XCTest setup/teardown, several UI test boundaries, locked notification collectors, async lock calls, and request recorders that previously transferred Foundation `Any` dictionaries between actors.

The checker matches file, diagnostic message and distinct occurrence count. Repeated batch-compiler output at the same source location counts once. Source line movement does not invalidate the baseline. A new message, a new file, or an increase in occurrences fails CI; replacing a resolved occurrence with another identical warning in the same file is not distinguished. Dependency checkout warnings are outside this first-party baseline. Compiler upgrades that change diagnostics need an explicit review rather than automatic baseline regeneration.

Reduce allowances after a successful complete Xcode build confirms a category has disappeared. Never add production allowances, silence warnings globally, or regenerate the baseline automatically in CI. Review any proposed increase against the actual isolation or ownership contract. The remaining fixture warnings stay visible in the uploaded build evidence, including native audio objects and asynchronous fake-service ownership.

WhisperKit 0.18 does not declare its mutable model instance Sendable. Sotto's private `SerializedWhisperKit` bridge has one owner, `WhisperEngine`, whose existing `transcriptionPermit` covers preparation, inference and unload across suspension. The bridge does not add a global or retroactive Sendable conformance to WhisperKit. All future accesses must retain that ownership rule; the separate ANE gate controls cross-engine hardware serialization on macOS 14.
